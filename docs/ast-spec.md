# 分科模擬考規格草稿

> 2026-11-09 草稿，**待調度員／使用者確認後才寫程式**。本文只記結構與規則，不含任何姓名、學號、帳號。

## 一、研究結論：使用者資料夾裡沒有分科資料

逐檔檢查使用者本機資料夾（15 個檔，修改日期都是 2026-11-07，與 `sample-analysis.md` 當時分析的是同一批）：

| 檔案類型 | 內容 | 是否分科 |
|---|---|---|
| 考生資料名單 E1～E4（xlsx，5 檔） | 組別代碼為學測的「國.英.數.社／自」「數學A／B」「x數B」等；沒有任何分科科目（數甲、物理、化學、生物、歷史、地理、公民）與「分科」字樣 | **否，全是學測** |
| 座位表 docx（含檔名「高三E1／E2／E3 分科模考」） | 內文標題為「【115學年第1／2／3次**學測**模擬考】」；檔名的「分科」是誤植（`sample-analysis.md` 第 135 行已記過） | **否** |
| 標籤 docx | 無標題文字，版型與學測同 | 否 |
| 高三、國三學生名單 | 班級、座號、姓名，與考試類型無關 | — |

**結論**：使用者說「上傳的分科模擬考的考試名單、座位分配」，但實際檔案沒有分科樣本。若使用者另有分科檔案，請放進該資料夾（或告知檔名），我才能歸納真實欄位與座位規則；否則下列規則只能是「由既有引擎與決定推得的暫定值」，不可當成已確認。

## 二、程式現況（origin/main）

- `ExamKind = 'gsat' | 'ast' | 'bcct'` 已含 `ast`；`store.ts` 的新增考試對 `ast` 直接擋下（「分科尚未開放」），新增考試頁分科卡灰階標「即將推出」。
- 排座引擎（全域輪流貪婪，D73）、驗證、抽離、標示、匯出都不依考試類型分支；D37 已決定「分科只差科目表、組別對照表、標示規則三份設定」。
- `src/ui/subjects.ts` 的 `defaultSubjects` 只處理學測與會考；分科要補一份。
- D64：考試名單有「部分參加」模式（分科預設），沒報名者不算差異，統計列顯示「未參加 N 人」。

## 三、暫定規則（全部「未確認」，來源：既有決定／需求，非實際資料）

1. **科目**：全部選考（requirements）。預設科目表暫定 8 科：數學甲、數學乙、物理、化學、生物、歷史、地理、公民與社會（P4、大考中心分科測驗科目）。不含英聽（D67 英聽屬學測）。可新增／刪除／編輯（D52）。
2. **文理組**：理組預設考數甲、物理、化學、生物；文組預設考歷史、地理、公民與社會、數乙（P4）。
3. **組別代碼**：每個考生的組別代碼對應一組考科。代碼表、格式（是否仍沿用學測的欄位「組別」、是否可能直接列科目）**完全未知**。匯入走現有「智慧欄位對應」；組別對照表由使用者在步驟④建立，程式依人數建議。
4. **標示**：只標與預設不同的人（標少數）。理組標「不考某科」或「加考歷史」等、文組標加考。標示邏輯沿用 D12：接近一半時由使用者選。
5. **座位排法**：沿用現有引擎：高中部分文理組教室，同班連續、跨教室輪流。分科人數可能遠少於全年級（D64 部分參加），教室數由使用者在步驟②設定。
6. **抽離**：沿用預備教室機制（文組加考理科者集中）。分科的實際需要未知。
7. **缺考**：現有學測規則是標示與「特殊生需求註明」無關、座位表不印缺考；分科未驗證。
8. **實作範圍（確認後）**：解除 `store.ts` 的分科擋下與新增卡的灰階；補 `defaultSubjects('ast')`、分科的 `subjectWho`（分科每科都依組別）、部分參加預設；補測試（假資料）；不動引擎、不動 `docs/design/`、`tokens.css`。預估小改動。

## 四、需使用者決定／提供（請調度員統一問）

1. **有沒有分科的實際檔案？**（考生資料名單、座位表）沒有的話，是否先照第三節的暫定值實作，第一次辦分科時再校正（P4 當初的做法）？
2. 分科的**組別代碼表**長什麼樣（大考中心分科測驗報名格式？每人直接列考科？）？
3. 分科**是否仍分文理組教室、不可混合**？還是依科目組合分場？
4. 預設科目是否為 8 科？學校實際只辦哪幾科？
5. 分科有第幾次、每次考科是否不同（會不會像學測第 1、2 與第 3、4 次不同）？
6. 是否需要抽離到預備教室？
7. 標籤要標「不考」還是「加考」？規則可否沿用學測？
8. 「未參加」的學生要不要出現在任何輸出（統計列之外）？

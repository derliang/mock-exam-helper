- 規格＝使用者提供的《分科模考智慧排程與座位分配 Claude 交接規格 V0.1》（草案，2026-11-09）。D99＝`docs/decisions.md` D99 三輪裁示＋D101。稿＝稿 v2.27～v2.33（以 `docs/design/DESIGN.md` 10.14、10.19 與 `docs/design/稿版號.md` 的文字為準）。測試＝`src/core/astD99/`（`contract.ts` 的 `checkPlan`／`labelsOf`、`d99.test.ts`）。
- **沒驗到**：稿欄是讀 DESIGN 與稿版號文字判斷的，**沒有逐頁開原型 HTML 對畫面**；寫「有畫」的只代表文字有寫，細節（例如標籤是否列空行）要對稿員逐頁核。
- 規格自己沒有給 CONFIG 編號，下表 CFG-1～CFG-6 是依 §2.3 六個項目順序自行編的。
- 測試狀態縮寫：**綠**＝驗證器真測試，現在就過；**fails**＝`it.fails`，引擎接上才轉綠；**todo**＝`it.todo`；**無**＝沒有。
- 「處理」欄用詞：要補測試／要補稿／要補實作／要問使用者／無需處理。

#### §13.1 八條驗證對應 `checkPlan` 的哪個檢查

| 規格 13.1 條目 | `checkPlan` 對應 | 狀態 |
|---|---|---|
| 每筆選考恰好一個時段、一個有效座位 | 逐生逐節 `exams.length !== 1` 與科目不符；座位存在檢查 | 有（時段唯一性靠 `takes: slot→subject` 構造保證） |
| 無同時段重複應試或考試／自習重疊 | `seen` 集合（同節同人只能出現一次） | 有 |
| 無教室同時段考試／自習混用 | `usage[roomId]` 與考試／自習身分不符 | 有 |
| 無座位重複、不存在座位、容量超載 | `used` 集合、`seatSet`、自習容量 | 有（考場容量由座位唯一性隱含） |
| 全部應到校未考者皆有自習；請假按設定排除 | 逐生「不考卻沒有恰好 1 間自習」 | **部分：沒有請假資料，無法排除** |
| 人工鎖定全部保留 | 無 | **缺** |

## D. 各包「開工前必讀補充」（規格 × D99；每條 ≤ 1 行出處）

### AST-1 分科引擎、教室資料、步驟③④⑤

1. 派工單寫的測試數量不對：實際 16 個 `it.fails`＋2 個 `it.todo`＋5 個綠的驗證器測試（G-29）。引擎接上後把 `it.fails` 改回 `it`，並設 `PLANNER`。

3. 教室的文理組判定（S-12／§4.1）在使用者裁示 R1 前，**不要把「依考生組別限制教室」寫成硬規則**，先以當節科目為準並在完工記錄註明，等調度員轉裁示。

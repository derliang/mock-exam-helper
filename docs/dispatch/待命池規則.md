# 調度員交接與待命池規則

> 使用者 2026-11-07 的規定。目的：調度員的對話用久了上下文會變長，需要換一個乾淨的對話接手；預先準備空白對話，交接時直接任命，不必臨時開新的。

## 規則

1. 使用者要求隨時保有 **5 個空白待命對話**，**專門用來交接調度員的工作**（不拿去做別的事）。空白對話只待命、不帶任務，各自用獨立 worktree。2026-11-08 已開出待命-11 到待命-15（建立時一律指定 `cwd` 為本專案資料夾、獨立 worktree，並立即 `detach_session` 脫離現任調度員，否則調度員被封存時會連帶受影響）；待命-6 到待命-10 當初誤開在 teacher-hub 專案底下，已封存；早先的待命-1 到待命-5 已被用掉或另作他用。用掉幾個、就問使用者要不要補回 5 個（見第 4 點）。
2. 當使用者指示「交接」，現任調度員要：
   1. 從待命池挑一個空白對話，用 `SendMessage` 傳完整的「調度員交接令」，讓它成為新的調度員。
   2. 自己收尾：把進行中事項、對話對照、待裁決事項寫進交接令與交接檔，確認已 push、worktree 乾淨；使用者說了「交接」就是授權封存舊調度員，由**新調度員**在接手第一步封存舊調度員（調度員技能規定調度員不封存自己，見〈調度員換手〉第 4、4a 點），效果等同「舊調度員收尾並封存」。
   3. 把**本規則全文**連同交接內容一起傳給新調度員，讓每一任都照做。
3. 新調度員接手後：第一步載入技能 `dl-dispatcher`，讀交接令與交接檔，核對 `list_sessions`，並向使用者回報待命池還剩幾個、哪幾個。
4. 待命池是否補回 5 個，由新調度員問使用者，不自行補。（暫定）
5. 被任命的待命對話，收到交接令前不得自行開工。收到後，在回報裡寫明「本規則已收到並會傳給下一任」。
6. 語言一律使用台灣繁體中文。

## 交接令必備內容

- 專案與儲存庫位置、目前分支與最後 commit。
- `docs/decisions.md` 的最新版本（已定、暫定、未決）。
- 進行中與待命的對話（session id）、待裁決事項、下一步。
- 本規則全文。

## 備註

- 待命對話在專案尚未成為 Git 儲存庫時共用同一個資料夾；專案成為 Git 儲存庫後，新開對話一律使用獨立 worktree。
- 本檔只記規則，不記對話的 session id；session id 由現任調度員在交接令中提供。

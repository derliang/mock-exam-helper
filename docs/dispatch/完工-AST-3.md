## 沒驗到／未完成／與稿的差異

- **教室用途鎖定只驗證、不強制**：引擎沒有「指定某教室某時段用途」的輸入；與鎖定不同時回報衝突、不能定案。要真的強制，要改引擎（放行訊息說不動 AST-2 輸出格式，沒說可不可動引擎，我選擇不動）。
- **班級考場鎖定**是後處理：把該班應考者換進指定教室的空位，違反硬性規則就放棄並回報；不保證找得到解（找不到會回報，使用者再調整）。
- **公告的標籤／班級公告「同一版」**靠「同一份方案、同一個版本碼」保證；版本清單存座位快照可比對差異，但**舊版的整份輸出（標籤、公告）不能重新下載**（只能看差異）。D99 沒採內容雜湊，這裡的版本碼沿用 AST-2 的資料版本碼（`dataVersion`，鎖定、沿用都算進輸入）。
- 沿用的移動只做同排內不越過鄰座的調整（沿用 `alignSeats` 的同一套限制）；跨排、跨教室的沿用不做，歸入「同教室不同座位／不同教室」並寫原因。一個人跨時段座位不同時，「同教室同座位」只要有任一時段相同就算。
- 稿的「請假」切換、版本清單「公告時」輸入修改項目欄位：稿有「修改項目」輸入框，實作改為**程式自動算**（新舊座位差異）；理由才讓使用者填。
- 稿的示範資料是假數字；實作全由名單與引擎算。「稿上選了非 A 候選後 ⑤ 仍以 A 示範」已改成依選定時程排座。
- 「僅管理者」怎麼落實未裁示（R4）：沒做權限，管理者核准＝畫面上按「管理者核准」。
- 沒用真實名單驗證（R9，使用者本機做）；沒實際在 Word／瀏覽器列印看過版面。
- 特殊生需求小牌、考場座位表下載、反向查詢：AST-2 完工記錄列過，本包放行範圍也沒有，沒做。

## 我替你決定的事（可推翻）

1. **後處理而非改引擎**：鎖定與跨次沿用放在 `refine.ts`，引擎不動，避免動到 AST-1／AST-2 已驗收的行為；代價是教室用途鎖定只能驗證。
2. **候選 B 的做法**：每天把第一科移到最後，用來示範「無改善」；真正的調序由管理者改節次表（基準 A 依節次表，不寫死）。
3. **候選 D 的時段數**＝基準每天最多的時段數，用回溯找「同時段沒有共同考生」的分法；找不到才標不可行。
4. **換時程會清掉替代方案核可與鎖定**（時段 id 變了，留著會指向不存在的時段）；畫面上有說明。
5. **規劃中不能下載**依稿 v2.35；已公告後的 ⑥ 下載與預覽照常。
6. **定案時存座位**當作下次跨次沿用的來源；「上次座位」每人只存一個座位（取最常坐的）。
7. 版本的「修改項目」自動算，不讓使用者輸入。

## 需要調度員／使用者決定

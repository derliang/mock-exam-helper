# 品質關卡（D70）

> 使用者 2026-11-08 要求：使用者審查實際程式前，要先做好品質管控，不用使用者除錯。

## 每個施工對話（交 PR 前）

1. 邏輯單位完成就要有可重跑的自動測試（單元，涉及畫面或流程的加端對端），不為湊數寫沒有意義的測試。
2. 交 PR 前相關測試全綠，完工回報附**指令與結果**；沒附證據退回。
3. 不自己併 main（A 軌）。push 的是工作分支。
4. 公開 repo：測試資料一律假資料，不得出現真實學生姓名、學號、帳號。

## 調度員（併 main 前）

1. 審 PR：範圍符合派工單、無學生資料、無無關改動。
2. 在該 PR 分支**自己重跑**測試（不信回報），綠燈才併 main；併入後在 main 再跑一次。
3. 紅燈：先讀輸出、對照 main、分類；同一錯誤連續失敗 2 次轉診斷。

## 全部完成後（交使用者前）

1. 程式功能全部併入 main、main 測試全綠。
2. **派驗收員**（使用者已於 D70 明確要求）對指定 SHA 驗收功能是否正常，涵蓋 requirements 的主要流程：初始化、學生名單、考試設定六步驟、排座、標籤與抽離、匯出。
3. 驗收不通過 → 調度員依重現證據重新派工 → 重驗；通過才交使用者。
4. 交使用者時附：版本 SHA、網址、驗收結論、已知限制。

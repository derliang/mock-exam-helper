# 使用者原始需求整理

> 來源：2026-11-07 使用者的需求說明（依原意整理，沒有加入我方推論）。推論與後續決定見 [decisions.md](decisions.md)。

## 一、整體

- 把使用者例行、複雜的模擬考行政工作，改由程式自動化。**程式成果必須 100% 正確**，使用者不用除錯。
- 要有精美的 UI 與良好的 UX。以桌機操作為主，特別重視桌機的頁面配置與功能性。
- 純 Web App，放在 GitHub Pages 執行；**GitHub 不放學生資料**。
- 所有學生資料都儲存在使用者本機。程式初始化時必須詢問使用者資料檔放在哪裡；需要的資料也都由本機匯入。
- 先滿足基本功能，基本功能完善後，使用者會逐步加入新功能。
- 首先要完成的是**座位的安排**。

## 二、情境

1. 模擬考分三種：學力測驗模擬考（學測）、分科測驗模擬考（分科）、國民教育會考模擬考（會考）。詳細考試科目、時間長度、規定請查大考中心與國中教育會考網站。
2. 會考模擬考由國中部學生參加，不分文理組。
3. 學測與分科模擬考由高中部學生參加，分文理組。
4. 高中部全部學生都要打散到各教室考試。原則上文組同學打散到文組班級教室，理組同學打散到理組班級教室；**不可把文理組合併**，方便老師發卷與點卷。國中部則把所有班級打散到所有教室。
5. 高中部第 1、2 次模擬考，數學不分數 A、數 B（一律叫數學）；第 3、4 次才分數 A、數 B。

## 三、設定功能

### 學生資料（區分國中部與高中部）

- 國中部：班級、學號、座號、姓名。高中部：另加文理組、選考科目。
- 除了在網頁上快速設定，也要能匯入、匯出，並提供下載範本檔。
- 匯入檔案的格式盡量與使用者原本用的檔案一致，要有智慧判斷欄位的功能，自動對應。
- 學生自動編號：第 1 班 1 號是 0101，第 5 班 35 號是 0535。

### 教室座位

- 可設定幾個班級教室、教室名稱、座位排列並計算座位數。排列可參考「座位小幫手」的設計，讓使用者自己設定行與列，並標示空座位；空座位不可排入學生。
- 另可設定**預備教室**，預備教室的座位數不納入班級教室座位數的計算。

## 四、主畫面：座位安排

### 排座原則

1. **深位**：排同一班的同學，編號要連續，方便老師發卷。
2. **橫排**：排不同班的同學，但文組班排文組教室、理組班排理組教室。國中部不分文理組，不受教室限制。
3. 所有學生都必須排到座位，座位數與考生人數必須相符。教室剛好剩幾個位子時，可再安排某班的同學，不受深位必須同班的限制；但必須同班連續。不同班的同學不可穿插在不同的深位（例：1、4、5 是甲班，2、3 卻是乙班）。

### 預覽與匯出

- 主畫面要有座位預覽，可切換班級預覽，也可選擇檢視幾個班級。
- 座位表可匯出 PDF 或 Word，**版面 A4**，標示第幾橫排、第幾深位、講臺在哪裡，供監考老師辨認。

### 座位標籤

- 主畫面要有列印座位標籤的功能。標籤上有大字的考生編號、小字的考生姓名，並明顯標示學生**不考什麼科目**。
- 標籤由使用者手動裁切，版面為 **B4 或 A3**，用表格呈現，依表格框線裁切，所以每格不要有間距。**每個班級可用不同底色**，方便發卷與監考。
- 標籤順序必須與座位表相同，方便張貼。

### 高中部學測的標示邏輯

- 理組：不考社會、不考數 B 要標示，其他科不標。
- 文組：不標示不考科目，要標示加考的科目。
- 以上標示規則都可由使用者參數化自訂。
- 學測理組預設考：國、英、數 A、英聽、自然，大部分會加考社會與數 B。文組預設考：國、英、數 B（或數 A）、社會、英聽，少部分會加自然。
- 分科測驗每一科都是選考；使用者請我方提問文理組預設考哪些科。
- 標示也許只要標少數人：例如理組不考社會的、文組考自然的。使用者請我方判斷並給規則參考。

## 五、預備教室的抽離

高中部可能有文組學生加考理組科目（例：文組考數 A）。這些學生因為人數不多或太多，要集中到預備教室考試，原教室留給不考試的同學自習。這要能設定。

## 六、範例資料

使用者提供高中部前三次模擬考的名單、座位表與標籤，以及國中部檔案，供我方學習規則。分析結果見 [sample-analysis.md](sample-analysis.md)。範例檔含學生資料，只留在使用者本機，不進本儲存庫。

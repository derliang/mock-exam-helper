# 施工分包・第二批（使用者 2026-11-08 新增四項需求）

使用者原話：
1. 目前程式對於正確的資料，可能正確率很高，但我要提升到 100% 正確。
2. 程式對於不正確的資料要有容錯與智慧判斷，尤其匯入時，資料可能錯亂、表頭不正確、用非正規方式標示考試科目；程式應從群體資料判斷有哪幾類標示方法，讓使用者手動對應。
3. UI 進一步優化，以優秀的 UI 設計引導使用者，避免犯錯，提升 UX。
4. 處理流程流暢，各頁面之間有正確的引路，避免使用者犯錯。

## 上下文紀律（使用者要求）
- 派工前一律量 `get_usage`：≥25 萬提醒並收尾、≥40 萬換手。2026-11-08 量測：A 24.5 萬（不再派新工）、B 11.1 萬、C 10.6 萬、D 10.8 萬、調度員 11.5 萬。
- 新的大包優先開全新對話；開不了才用 ≤15 萬的現成對話。

## 分包

| 包 | 內容 | 分支 | 檔案範圍（鎖） | 負責 |
|---|---|---|---|---|
| **E 智慧匯入** | 需求 2。(a) 表頭偵測容錯：表頭列錯位、合併儲存格、多餘空列、欄名同義詞／錯字／全半形。(b) **科目標示分群**：掃描整份考試名單，列出「出現過的各種標示寫法」（如「國」「國文」「Ch」「✓」「○」「1」…）及次數，依群體相似度分組，讓使用者逐組手動對應到科目／或標為「忽略」；對應結果可存、可重用。(c) 無法判斷的列進「待確認清單」，不得默默丟棄或猜測。(d) 匯入預覽（變更前後差異、錯誤列清單）、確認後才寫入。 | `build/e-smart-import` | `src/import/`（新增檔為主）、`src/ui/pages/ImportWizard*` | C（≈10.6 萬） |
| **F 正確性 100%** | 需求 1。以不變式與性質測試把關：座位表必須「每位考生恰一座、無重複、無遺漏、只在合法座位、連續學號、空位只在最後」；抽離分配守恆；匯入→存檔→讀回→匯出往返一致；Word／PDF 輸出人數、座位與畫面資料逐筆比對；用去識別化的真實版面結構做回歸。找到的任何錯誤當場開 issue 並修（小的）或回報（大的）。完工附「不變式清單」。 | `build/f-correctness` | `src/**/*.test.ts`、`tests/`；發現缺陷才動 `src/core`、`src/export` | 全新對話 |

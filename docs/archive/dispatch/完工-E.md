# 完工記錄・E 智慧匯入（施工C，分支 build/e-smart-import）

需求來源：`施工分包-第二批.md`〈E〉＝使用者需求 2（匯入對錯亂資料要容錯與智慧判斷）。測試資料全是假資料。

## 做了什麼
| 規格項目 | 實作 | 檔案 |
|---|---|---|
| (a) 表頭偵測容錯 | 欄名錯字（差一字，如「坐號」）、全半形、括號註記（「學號(選填)」）、英文欄名、包含關鍵字（「學生座號」）；表頭前有標題／空列／欄位不在第一欄；表頭被合併儲存格拆成上下兩列 | `src/import/smartHeader.ts` |
| (b) 科目標示分群 | 掃描備註欄、加考欄、以及「表頭就是科目名」的科目欄；標示切開（頓號、逗號、空白…）、連寫縮寫拆字（缺國英）、前綴語意（缺／加）；依相似度分組（國／國文／國語文；CH／CHINESE；✓／✔；數A 與 數 不併）並計次；每組給「建議科目」但**不自動採用**，使用者逐組選科目或「忽略」 | `src/import/marks.ts` |
| 對應可存可重用 | `rememberMapping`／`prefillMapping`：同組成員記錄一致才預填，衝突留給使用者；存在 `settings.markMap`（新增的選填欄位，隨資料夾保存） | `marks.ts`、`src/data/types.ts` |
| (c) 待確認清單 | 班級座號看不懂、沒姓名、座號重複、組別不在對照表 → 每列要明確「套用修正」或「略過」，未處理不能匯入；說明列／空白列另計並可展開檢查，不默默丟棄 | `src/import/smartScan.ts` |
| (d) 匯入預覽 | 新增／變更（姓名、科目、組別，前→後）／移除／不變；移除者警告；確認才寫入，之前取消不改任何資料；寫入是一次 onChange，可復原 | `smartScan.ts`（`diffEntries`）、`src/ui/pages/ImportWizard.tsx` |
| 畫面 | ② 頁的匯入改走精靈：欄位確認 → 標示對應 → 待確認 → 預覽；「確認匯入」旁寫明還缺什麼 | `ImportWizard.tsx`、`Step2.tsx`（只改匯入入口） |

單元測試：`src/import/smart.test.ts`（錯亂表頭、混用標示、全半形、空列、說明列、重複、缺班級欄、對應重用、差異預覽）。

## 我替你決定的事
- `Step2.tsx` 與 `src/data/types.ts`（`Settings.markMap?`）不在原定檔案鎖內，但精靈要接入口、對應要隨資料夾保存，改動都很小且向下相容；舊的 `parseExamWorkbook` 保留未動。
- 標示只掃備註／加考／科目欄；不掃姓名、座號、班級等欄。備註裡超過 6 字的整句說明視為說明文字，原樣留在考生備註，不當標示。

## 沒驗到
- 沒用真實檔案與真實瀏覽器上傳實測精靈畫面（無 jsdom 元件測試；檔案選擇需手動）。
- 「兩列合併表頭」只處理上下兩列；橫向合併儲存格因 xlsx 讀取器只回傳左上格，欄位位置靠表頭文字判斷。
- 真實檔案若出現本記錄未列的標示寫法，會成為新的一組讓使用者手動對應（設計如此），不會出錯。

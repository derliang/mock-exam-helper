## 1. 使用者定的鐵則（違反會被罵，且已發生多次）

1. **四步順序不可跳**：①稿修正到最新最正確 → ②派對稿員比對實作與稿 → ③修正實際頁面與稿完全一致 → ④調度員發布正式站。使用者說「稿可以」只代表進入②，不是③。
2. **稿是基準**：實作中發現稿要改，**先回頭改稿**（升版號、更新 `稿版號.md`、重發成品），commit 訊息寫「為什麼改版」；不可默默改稿，也不可不照稿實作。
3. **看稿只用「成品」（Artifact 連結）**，不給檔案、截圖或 PR 連結當作看稿方式。只給「原型」連結（它含所有程式頁面，設計系統不用給）。
4. 稿有版號「稿 v2.N」（`<title>`、頁首徽章、`稿版號.md`、成品標題四處一致）；**每次稿變就升**，三份稿（原型、設計系統、拉皮稿）版號同步，漏一份會被抓。
5. 要使用者回答的問題一律用問題卡（AskUserQuestion），選項附優缺點、建議項排第一；不在聊天裡問開放式問題。
6. **結構、新增畫面、版面改動要先問使用者**（只改外觀的拉皮才可直接做）。分科教室分法就是我誤把別人的「建議」當定案畫進稿，被使用者糾正（見 D95）。
7. 回報格式最後固定兩行：「我替你決定的事」「已用問題卡問」。沒驗到的地方要老實講（例：820 寬度沒看）。
8. 稿通過前**不進實作**；不自己合併實作 PR（調度員合併）。稿的 PR 使用者明說「commit and push github main」才合併進 main（#111 已這樣處理）。

## 5. 工作方法與踩坑（省你重新踩一遍）

- 驗證：用 headless Chrome（repo 的 `scripts/compare-shots/cdp.mjs`，參考 `launchChrome`、`Browser`），量橫向溢出（`scrollWidth-innerWidth`）、看截圖；寬度 375／820／1280，淺／深色。沒看的寬度要在回報寫「沒驗到」。
- **工具陷阱**：本機沒有 Python，用 node 腳本；bash heredoc 會吃反斜線，內容含反斜線、反引號或很長就用 Write 工具寫檔再執行；PowerShell 5.1 不要用管線覆寫含中文檔；中文路徑的 git 指令加 `git -c core.quotepath=false`。
- 改很大的 `原型.html`（約 25 萬字元）：用 node 腳本做「唯一匹配替換」（匹配數不是 1 就丟錯），改完 grep 確認、跑一次驗證腳本。
- **主工作目錄常停在舊分支**：`git pull` 顯示最新只代表該分支，不代表 `origin/main`（2026-11-09 主目錄停在 `docs/optional-features`，落後很多）。規範一律從 `origin/main` 或 PR 分支取；寫入開獨立 worktree。
- **成品發佈（現行工具）**：用 `mcp__claude-artifacts__publish_files`，`files` 帶 `{"as":"index.html","path":"<絕對路徑>"}`，更新同網址要帶 `slug` 與 `base_version`（先 `get_artifact` 取當下 version）；slug：原型 `9a42c0fd-a799-48db-bcbb-2f035c8a6eee`、設計系統 `7f7bb72f-9914-4606-aacd-b45886bd908e`、拉皮稿 `4e8f6dce-1d27-4df2-89f3-c7b99bc0f818`。發佈規定要先整份讀過檔案（三份合計約 53 萬位元組，交子代理讀與發佈，別灌進主對話；`設計系統.html` 第 713 行是 14 萬字元的 SVG，上次沒逐字讀，改用指令查過標籤與文字）。完成後用 `get_artifact` 核對標題。小心：發佈會**覆蓋同網址的上一版**，所以「使用者通過的基準」被新稿覆蓋前要確定可以（v2.15 曾被我誤蓋，已還原）。
- 新 worktree 要先 `npm ci` 才能過 pre-push（`npm run typecheck && npm test`）；npm 快取壞時加 `--cache <暫存資料夾>`。
- commit 識別：`git -c user.name="Claude-<裝置簡稱>" -c user.email="noreply@anthropic.com"`，結尾加 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`；不強推；不自己合併實作 PR。
- 額度：使用者額度有限，2026-11-09 已要求各對話施工暫停。沒有使用者明確指示不要主動大量讀檔或重做；大範圍重做先問要不要一次做完。
